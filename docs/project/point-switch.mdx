# Point Switch

스위치를 아래로 당기면 광고가 열리고, 완료하면 다이얼 한 칸이 채워집니다. 열 칸을 채운 뒤에는 마지막 지급 광고가 따로 있습니다. 화면에서는 반복 동작을 짧게 만들고, 서버에서는 충전과 실제 지급의 책임을 나눴습니다.

## 화면으로 보는 기능

**스위치**는 끌어당기는 거리에 반응하고 중간에 놓으면 돌아옵니다. **다이얼**은 오늘의 충전 횟수를 표시합니다. **광고 완료**와 **지급 완료**는 같은 이벤트로 취급하지 않습니다. 네트워크가 끊기거나 화면을 다시 열어도 지급 상태를 확인하는 과정이 필요하기 때문입니다.

갤러리는 로컬 테스트 모드에서 7→8회 충전한 화면입니다. 실제 토스 로그인이나 포인트 지급까지 검증한 캡처가 아닙니다.

## 응답이 없을 때 다시 지급해도 될까

지급 API의 응답이 끊겨도 외부에서는 이미 처리가 끝났을 수 있습니다. 이때 같은 지급 동작을 무조건 다시 실행하면 중복 지급 위험이 생깁니다.

| 상황                     | 구현한 처리                            |
| ------------------------ | -------------------------------------- |
| 액션 시작                | 세션에 묶인 만료 시간·일회성 티켓 발급 |
| 같은 완료 요청 재전송    | 멱등키와 소비 상태 확인                |
| 지급 요청 수락           | DB 작업으로 저장하고 작업자가 처리     |
| 지급 실행 뒤 응답 불명확 | 실행 결과 조회로 상태 확인             |
| 작업자 교체·중단         | 임대 상태와 오래된 작업 점검           |
| 연결 해제                | 대기 상태를 정리하고 후속 지급 제한    |

티켓은 재전송을 관리하는 장치이지 실제 광고 시청을 암호학적으로 증명하는 장치는 아닙니다. 운영 전환에는 광고 파트너의 완료 검증과 부정 사용 방어가 더 필요합니다.

## Recent Notes

소개 기준은 **2026.08.22의 main 브랜치**입니다. 9월에 갱신된 의존성 자동 업데이트 브랜치는 아직 합쳐지지 않아 현재 기능이나 출시 버전으로 계산하지 않았습니다.

2026.09.13에 API 테스트 **22개를 실행해 통과**했습니다. 티켓 소비, 재시도, 외부 응답 형태, 연결 해제와 마이그레이션 관련 로직을 확인했습니다.

## Next

실제 지급을 켜려면 토스 로그인·mTLS, 운영 DB와 작업자, 광고 그룹, 예산과 지급 승인 설정이 필요합니다. 현재 페이지는 비공개 테스트 구현을 소개하며 운영 리워드 서비스가 아닙니다.
