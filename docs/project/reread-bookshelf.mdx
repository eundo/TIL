# Reread Bookshelf

읽은 책을 다시 찾을 때 제목보다 장면이 먼저 떠오를 때가 있습니다. 재탕 책장은 제목과 작가 옆에 인물, 관계, 분위기, 메모를 함께 저장합니다. RIDI·시리즈·카카오페이지 링크를 한 책장에 모으되, 기록은 우선 내 기기에 남깁니다.

## 샘플 책장 데이터

캡처에는 실제 개인 독서 기록 대신 고전 6권과 직접 작성한 메모를 넣었습니다.

| 작품                 | 기억 단서                           | 기록                |
| -------------------- | ----------------------------------- | ------------------- |
| 오만과 편견          | 엘리자베스, 다아시, 오해에서 이해로 | 재독 1회, 장면 메모 |
| 작은 아씨들          | 가족, 성장                          | 재탕 후보           |
| 데미안               | 성장, 선택                          | 재탕 후보           |
| 어린 왕자            | 여행, 관계                          | 완독                |
| 이상한 나라의 앨리스 | 모험, 판타지                        | 완독                |
| 월든                 | 자연, 기록                          | 완독                |

## 화면별 설명

### 책장과 상세 시트

목록에서 최근 재독과 인물 단서를 확인하고, 작품을 열어 메모를 이어 씁니다. `오늘 +1`은 재독 이력을 추가하는 동작입니다. 단순 횟수만 올리는 대신 날짜와 당시의 짧은 감상을 함께 보관합니다.

### 구매목록 가져오기

RIDI 구매목록의 XLSX·XLS·CSV를 읽고 저장 전에 새 작품과 기존 연결을 구분합니다. 샘플에서는 기존의 오만과 편견·작은 아씨들에 구매 정보만 연결하고, 변신을 새로 추가했습니다. 다시 같은 파일을 읽어도 개인 메모와 수정한 정보를 덮어쓰지 않도록 병합합니다.

제목과 작가 열을 확인할 수 없는 파일은 추측해서 가져오지 않습니다. 표지나 원문 링크도 파일에 없는 값을 임의로 만들어 넣지 않습니다. 시리즈·카카오페이지는 링크 또는 수동 등록 대상이며, 이 구매목록 파일 파서와는 구분됩니다.

### 삭제와 복구

삭제한 작품은 휴지통으로 이동합니다. 최근 저장 상태는 최대 5개의 복구본으로 남기고, 작성 중인 입력은 초안으로 보관합니다. 실수로 지웠을 때의 복구와 브라우저 데이터를 모두 지웠을 때의 복구는 다릅니다. 후자는 별도로 내보낸 백업 파일이 필요합니다.

## Latest Notes

**2026.09.07 기준**으로 소개와 화면을 갱신했습니다. 현재 주 저장소는 localStorage가 아닌 IndexedDB입니다.

- 이전 localStorage 데이터는 원본을 보존한 채 한 번 이전합니다.
- 작품·이미지·휴지통을 하나의 저장 트랜잭션으로 처리합니다.
- 저장 리비전을 비교해 오래 열린 탭이 최신 기록을 덮어쓰지 않게 합니다.
- 휴지통, 입력 초안, 최근 복구본, 구매목록 미리보기와 중복 병합을 추가했습니다.
- 포함·제외 태그와 전체·일부 일치 조건을 조합하고 검색 조건을 저장합니다.

## What It Does

작품 정보, 재독 이력, 발췌 이미지와 메모를 한 단위로 관리합니다. 인물 이름이나 기억나는 문장도 검색 대상입니다. 링크에서 정보를 읽지 못하면 수동 입력을 계속할 수 있고, 스크린샷 OCR 결과는 저장 전 수정할 수 있습니다.

## 모바일에서 중요한 것

책장 위치를 유지한 채 추가·상세·발췌 시트가 열립니다. 열린 시트는 브라우저 뒤로가기와 연결했습니다. 표지 숨김과 간단 보기로 공개 장소에서의 노출을 줄일 수 있고, 설정에서 저장 상태와 데이터 삭제 범위를 확인합니다.

## 동작 흐름

`등록 → 기억 단서 기록 → 검색·재독 → 백업`

입력 방식을 여러 개 제공하더라도 저장 결과는 같은 작품 구조로 모읍니다. 이후 검색과 백업이 등록 경로에 따라 달라지지 않게 하기 위해서입니다.

## 저장과 복구 검증

2026.09.13에 핵심 로직·저장소·OCR 관련 **17개 테스트를 실행해 통과**했습니다. 데이터 이전, 구매목록 병합, 저장 실패와 오래된 리비전, 동의 없는 OCR 호출 차단을 확인하는 범위입니다. 실제 사용자의 모든 브라우저 환경을 검증했다는 의미는 아닙니다.

## Implementation Notes

JSON 백업에는 현재 작품과 연결된 이미지가 함께 들어갑니다. 참조한 이미지가 누락되면 성공한 백업처럼 처리하지 않습니다. 작성 초안과 내부 복구본은 내보내기 대상에서 제외됩니다.

OCR은 사용자가 동의하고 실행한 경우에만 서버 기능을 호출합니다. API 키는 브라우저에 넣지 않습니다. 이미지 인식이 실패하더라도 수동 등록 경로는 남습니다.
